## 2026-09-29 · redesign fix: search dropdown rendering behind page content (on branch redesign, not live yet)
- **What changed:** The search dropdown on the Articles page was rendering behind the topic tiles below it instead of on top of them, so the tiles' background color showed through the dropdown card. Root cause: the section holding the search box has the same gentle "rise into place" animation used across the redesign, and it turns out that kind of animation quietly changes how the browser stacks page elements on top of each other, even after the animation itself has long finished — in this case it was accidentally trapping the dropdown's own layering setting so it could never actually win against the section below it, no matter how high that setting was turned up. Fixed by explicitly telling that whole section it belongs above the content below it, rather than relying on the dropdown alone. Confirmed with a proper test (not just a glance at a screenshot, which turned out to be genuinely misleading here because of how a browser window crops a tall floating panel) that the dropdown now sits cleanly on top of the tiles, with zero exceptions, in light mode, dark mode, and at phone width.
- **Why:** Owner review of the previous preview caught this with a real screenshot.
- **How to undo:** this is on the redesign branch, not merged — reset the branch to the prior commit (a67384d) to remove just this fix. Nothing on the live site is affected either way.

## 2026-09-29 · redesign fix: search results dropdown (on branch redesign, not live yet)
- **What changed:** Typing into the search box on the Articles page was showing one giant underlined wall of run-together text — every result mashed together with no spacing, default blue-link styling, and the whole matched sentence highlighted. Root cause: the styling for search results was written correctly, but it was attached in a way that only works for content built when the page loads — search results are built afterward, the moment you type, so none of that styling was ever actually reaching them. Rewired it to use the always-on styling approach the site already uses elsewhere for this exact situation (the newsletter sign-up box has the same kind of "built after the page loads" content). Now each match shows as one clean row: a small colored topic label (the same style used on the topic tiles elsewhere on the site), the real article title in bold, and one short two-line snippet with just the matching word or two highlighted — not the whole sentence. Rows are separated by a thin line, capped at 5 results, and you can now use the up/down arrow keys to move between them and Enter to open the highlighted one, Escape to close. A related, smaller bug was also caught and fixed along the way: a Reflection essay's small colored category label had actually been invisible (unstyled) since it was introduced last session — fixed as part of the same underlying cause.
- **Why:** Owner review of the session 5 preview caught this — a real screenshot showed the problem clearly, which is why it wasn't caught before (checking that the right pieces exist on the page isn't the same as looking at how they actually render).
- **How to undo:** this is on the redesign branch, not merged — reset the branch to the prior commit (28847ac) to remove just this fix. Nothing on the live site is affected either way.
